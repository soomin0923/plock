# 파서 평가 (규칙 · LLM · 하이브리드)

자연어 일정 입력("내일 오후 3시 팀 회의")을 세 가지 방식으로 파싱해, 직접 라벨을 붙인 정답과 비교합니다.
앱 화면과 무관하게 PC에서 실행하는 오프라인 평가입니다.

| 방식 | 내용 |
|---|---|
| `rule` | 내장 한국어 규칙 파서 (`src/lib/nlParser.ts`). 비용 0, 네트워크 없음 |
| `llm` | Gemini (`src/lib/gemini.ts`, 앱과 같은 프롬프트) |
| `hybrid` | 규칙이 날짜 표현을 찾은 문장은 규칙 결과, 못 찾은 문장만 LLM |

## 1. 정답 데이터 만들기 (`eval/dataset.csv`)

`eval/dataset.example.csv`를 복사해 `eval/dataset.csv`로 만들고 엑셀이나 메모장으로 채웁니다.
예시 20줄은 형식을 보여 주기 위한 것입니다. **평가에는 본인이 쓴 문장을 쓰세요.**
파서를 만든 쪽이 쓴 문장은 파서가 잘 읽는 표현으로 치우쳐서, 규칙 방식 점수가 실제보다 높게 나옵니다.

| 열 | 내용 |
|---|---|
| `id` | 번호 |
| `ref_date` | 그 문장을 입력했다고 가정하는 날 (`2026-10-08`). "내일"은 이 날 기준으로 계산합니다 |
| `text` | 입력 문장 그대로 |
| `kind` | `event`(일정) / `task`(할 일) / `habit`(반복 습관) |
| `date` | 일정 시작일 또는 할 일 마감일. 날짜가 없는 할 일은 비움 |
| `end_date` | 여러 날 일정의 마지막 날. 하루짜리는 비움 |
| `start_time` | `HH:mm` 24시간제. 문장에 숫자 시각이 없으면 비움 |
| `expr_type` | 표현 유형 (아래 표). 유형별 정확도를 따로 냅니다 |
| `note` | 메모 (채점하지 않음) |

**라벨 규칙 (먼저 정하고 끝까지 같은 기준으로)**
- 한 주는 월요일~일요일입니다. "다음 주 수요일" = 다음 월~일 주의 수요일. 앱의 두 파서도 같은 기준입니다.
- "2시"처럼 오전/오후가 없으면 상식적인 쪽(대개 오후)으로 라벨하고, `note`에 적어 두세요.
- "점심", "저녁"처럼 숫자 시각이 없으면 `start_time`은 비웁니다.
- 날짜가 없는 할 일은 `date`를 비웁니다.
- 기준이 애매한 문장은 `expr_type`을 `애매함`으로 두고 따로 봅니다.

**문장 구성 권장 (100개 내외)**

| expr_type | 비율 | 예 |
|---|---|---|
| 상대 날짜 | 15% | 내일 3시 치과, 모레 저녁 7시 약속 |
| 요일 | 15% | 금요일 오전 10시 회의 |
| 주 단위 | 15% | 다음 주 수요일 발표, 이번 주 토요일 |
| 절대 날짜 | 15% | 10월 20일 면접, 11/3 2시 |
| 마감 | 10% | 다음 주 월요일까지 과제 제출 |
| N일 후 | 5% | 3일 뒤 병원, 2주 후 시험 |
| 기간 | 10% | 금요일부터 일요일까지 여행 |
| 날짜 없음 | 5% | 책 반납하기 |
| 애매함 | 10% | 이번 주말 대청소, 오후에 은행 |

평소 플래너에 실제로 적던 표현을 쓰세요. 예전 캘린더 제목을 참고해도 좋습니다.

## 2. 실행

```bat
cd D:\plock
npm install

:: 규칙 방식만 (API 키 불필요)
npm run eval -- --data eval/dataset.csv

:: 규칙 + LLM + 하이브리드
set GEMINI_API_KEY=AIza...여기에_키
npm run eval -- --data eval/dataset.csv --llm
```
- PowerShell에서는 `$env:GEMINI_API_KEY="AIza..."`로 키를 넣습니다.
- 모델을 고정하려면 `set GEMINI_MODEL=gemini-…`를 씁니다. 없으면 앱처럼 최신 Flash 모델을 자동으로 고릅니다.
- 무료 키 한도 때문에 LLM 호출 사이에 4.5초씩 쉽니다(`--delay 4500`). 100문장이면 약 8분 걸립니다.
- LLM 응답은 `eval/.cache/`에 저장됩니다. 라벨만 고쳐서 다시 돌릴 때는 API를 다시 부르지 않습니다. 새로 받으려면 그 폴더를 지우세요.

## 3. 결과

`eval/results/<시각>/`에 저장됩니다.
- `summary.md`: 방식별 필드 정확도, 표현 유형별 날짜 정확도, LLM 응답 시간(평균/p50/p95)과 실패 수, 하이브리드의 LLM 호출 비율, 틀린 문장 목록
- `rows.csv`: 문장별 정답과 세 방식의 예측. 엑셀에서 열어 오답을 직접 분류하세요

**해석할 때**
- 문장 수가 적으면 1문장 차이가 몇 %p 차이가 됩니다. 결과에 n을 함께 쓰세요.
- 정답은 본인 한 사람이 붙였습니다. 기준을 문서로 남기고, 한계로 적으세요.
- 하이브리드 규칙(“규칙이 날짜를 찾으면 규칙”)은 하나의 설계 선택입니다. 결과를 보고 바꿔 보세요. 예: 기간 표현만 LLM, 두 결과가 다를 때만 LLM. 바꾼 이유와 전후 숫자가 그대로 이야깃거리가 됩니다.
